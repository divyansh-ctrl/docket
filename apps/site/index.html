Ship agent work you can actually review.

how_it_works

Six stages. One human decision.

The controller owns the conversation and is never silently replaced. Workers receive bounded units, and nothing merges without you.

  1. 01 / PLAN

    A request becomes bounded units

    Mixed work is split into independently reviewable pieces, each labelled with risk and data policy.

  2. 02 / ROUTE

    Each unit earns its model

    Routing picks the cheapest model that has passed certification for that kind of work, and records the placement.

  3. 03 / EXECUTE

    Work runs isolated

    A Git worktree separates changes; a container, network policy, and scoped credentials form the real boundary.

  4. 04 / VALIDATE

    Deterministic gates, not assurances

    Checks run before anything is offered to you, and a failed gate stops the unit rather than narrating around it.

  5. 05 / APPROVE

    You decide, on evidence

    Intent versus diff, affected invariants, risk hotspots, and the exact decisions still required.

  6. 06 / INTEGRATE

    Only then does it land

    Approval is the gate. AOS never approves, merges, or ships its own work.

route_receipt

Proof, not vibes.

Every run produces an append-only receipt: the model requested and the model actually reported, where it ran, which gates passed, what it cost, and every escalation. If a provider will not report model identity, the receipt says so.

principles

What AOS refuses to do.

Authority

Never swap your controller

Connecting AOS cannot force Codex or Claude Code to replace its main model. A controller switch applies to new sessions only.

Evidence

Never claim unverified work

If no worker model produced an artifact, the run reports nothing rather than inventing a plausible summary.

Placement

Never move data by accident

Local, private, and hosted endpoints sit behind one policy surface. Eligibility follows workspace policy, not prompt wording.

Isolation

Never treat a branch as a sandbox

A worktree keeps history clean. A container, default-deny egress, and scoped credentials are what actually contain a run.

Credentials

Never touch your tokens

Provider login runs in the provider's own flow. AOS neither reads nor stores credential files or terminal input.

People

Never dress models as coworkers

No virtual office, no personas. Work units and their evidence, because that is what you review.

download

Run it locally.

AOS Desktop detects your installed Codex and Claude Code CLIs, runs their own login flows in a restricted terminal, and starts a fresh session in a workspace you authorise. It never attaches to or resumes an existing conversation.

Read this before installing

  • Unsigned Gatekeeper, SmartScreen, and unsigned Linux packages will each warn on first launch. Signing is a release gate that has not been met.
  • Verify Every release ships SHA256SUMS.txt, generated beside the artifacts.
  • Bring your own CLI AOS drives your existing Codex and Claude Code installs. It never bundles or replaces them.
  • Preview data Missions, costs, and receipts in the app are labelled demonstration data. No worker fleet or billing system is connected.
