not a permanent claim about competitors or model capabilities.

## Research standard

- Prefer first-party documentation, repositories, model cards, surveys, and
  standards over aggregator summaries.
- Preserve the difference between a documented capability, an anecdotal user
  report, an inference, and a product hypothesis.
- Include the review date for fast-moving competitors, models, pricing, and
  licenses.
- Treat absence from public documentation as “not established in the reviewed
  sources,” never as proof that a capability does not exist.
- Re-check model licensing, hardware requirements, product behavior, and market
  positioning before using this research for a launch or procurement decision.
- Do not copy a competitor's visual identity, proprietary assets, or product
  text into the application.

## Adding research

Use a descriptive lowercase kebab-case filename, state the question and method,
cite sources next to supported claims, and add the artifact to this index. Put
raw machine-readable evidence beside the analysis only when it contains no
secrets or private customer material.
